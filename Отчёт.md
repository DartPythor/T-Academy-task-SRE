## 1. Доменная область приложения

Vacancy Analyzer — сервис для автоматизированного **сбора, анализа и скоринга вакансий**. Приложение решает задачу оценки качества и безопасности вакансий для соискателей.

### Ключевые процессы домена

1. **Ingestion (сбор вакансий)** — получение данных о вакансиях из различных источников (Telegram-каналы, сайты карьеры, job-board'ы)
2. **Скоринг безопасности (Scam Detection)** — выявление подозрительных вакансий на основе набора сигналов (отсутствие компании, слишком высокая зарплата, подозрительные URL и т.д.)
3. **Оценка привлекательности (Apply Scoring)** — оценка того, насколько стоит откликаться на вакансию (наличие зарплаты, компании, описание, навыки)
4. **Расчёт уверенности (Confidence)** — метрика, показывающая, насколько полные данные о вакансии
5. **CRUD-операции** — управление источниками, компаниями, вакансиями

### Бизнес-ценность

- Снижение риска для соискателей (выявление мошеннических вакансий)
- Экономия времени за счёт автоматического скоринга
- Структурированное хранение данных о рынке труда

## 3. Основные сущности доменной области

### 3.1 Source (Источник вакансий)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Идентификатор |
| `name` | str | Название источника (уникальное) |
| `type` | SourceType | Тип: telegram_channel, career_site, job_board, other |
| `url` | str | URL источника |
| `enabled` | bool | Флаг активности |

**Поведение:** enable(), disable()

### 3.2 Company (Компания)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Идентификатор |
| `name` | str | Название компании |
| `website` | str? | Веб-сайт |
| `description` | str? | Описание |

### 3.3 Skill (Навык)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Идентификатор |
| `name` | str | Название навыка (уникальное, lowercase) |

**Immutable value object** — frozen dataclass.

### 3.4 Vacancy (Вакансия) — центральная сущность

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Идентификатор |
| `source_id` | UUID | Ссылка на источник |
| `external_id` | str | ID вакансии во внешнем источнике |
| `title` | str | Название вакансии |
| `description` | str | Описание |
| `url` | str | URL вакансии |
| `location` | str? | Локация |
| `employment_type` | EmploymentType? | Тип занятости |
| `work_mode` | WorkMode? | Формат работы (remote/hybrid/office) |
| `published_at` | datetime? | Дата публикации |
| `status` | VacancyStatus | Статус: new → processed → archived |
| `raw_data` | dict | Сырые данные из источника |
| `skills` | list[Skill] | Навыки (M2M) |
| `metric` | VacancyMetric? | Метрики (1:1) |

**Поведение:** add_skill(), attach_metric(), archive()

### 3.5 VacancyMetric (Метрики вакансии)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Идентификатор |
| `vacancy_id` | UUID | Ссылка на вакансию |
| `salary` | SalaryRange | Зарплатная вилка (VO) |
| `scam_score` | ScamScore (0-100) | Оценка подозрительности |
| `apply_score` | ApplyScore (0-100) | Оценка привлекательности |
| `confidence` | Confidence (0.0-1.0) | Уверенность в расчётах |
| `details` | dict | Детали расчёта |

### 3.6 Value Objects

| VO | Поля | Валидация |
|----|------|-----------|
| **Money** | amount (Decimal), currency (Currency) | amount ≥ 0 |
| **SalaryRange** | min_amount (Money?), max_amount (Money?), gross (bool?) | min ≤ max, единая валюта |
| **ScamScore** | value (int) | [0, 100], suspicious при ≥70 |
| **ApplyScore** | value (int) | [0, 100], verdict: apply/maybe/skip |
| **Confidence** | value (float) | [0.0, 1.0] |

### 3.7 Скоринговые модели

**ScamDetector** — линейная модель из 7 сигналов:
| Сигнал | Вес | Условие |
|--------|-----|---------|
| no_company | 20 | company_id is None |
| short_description | 10 | длина описания < 200 символов |
| no_salary | 15 | зарплата не указана |
| urgent_language | 15 | ключевые слова: "срочно", "быстрый доход" и т.д. |
| contact_only_messenger | 15 | контакт только через мессенджер |
| too_good_salary | 20 | max salary > 500k при коротком описании |
| suspicious_domain | 10 | URL содержит bit.ly, tinyurl, t.me/joinchat |

Максимальный score: 100. **ApplyAdvisor** — 6 позитивных сигналов + штрафы за scam и низкую уверенность.

## 4. Соответствие 12 факторам

### Фактор I: Кодовая база (Codebase)

**Статус: СООТВЕТСТВУЕТ (90%)**

- ✅ **Одна кодовая база** — весь проект в одном Git-репозитории (monorepo)
- ✅ **Множество деплоев** — один и тот же код разворачивается в dev (docker compose), staging и production
- ✅ **Система контроля версий** — Git
- ✅ **Чёткое разделение** — backend/ и frontend/ в одном репозитории
- ❌ **Нет Git-тегов** — отсутствуют версионные метки для привязки деплоя к версии кода
- ❌ **CHANGELOG.md существует** ✅ (создан)

> Обоснование: монорепозиторий, общая кодовая база для всех окружений. Единственное отступление — отсутствие git-тегов для релизов, что не нарушает принцип, но снижает traceability.

---

### Фактор II: Зависимости (Dependencies)

**Статус: СООТВЕТСТВУЕТ (95%)**

- ✅ **Явное объявление** — все зависимости в `pyproject.toml`
- ✅ **Изоляция** — Docker-контейнер, Poetry virtualenv
- ✅ **Lock-файл** — `poetry.lock` гарантирует воспроизводимость
- ✅ **Dev-зависимости** — pytest, mypy, ruff, pytest-asyncio, pytest-cov отдельной группой
- ✅ **Dockerfile через Poetry** — multi-stage build: установка через `poetry install --only main`
- ✅ **requirements.txt удалён** — Poetry — единственный источник истины
- ❌ **Нет CI-проверок** — `poetry check` и `poetry lock --check` не интегрированы в CI (т.к. CI пока не настроен)

> Обоснование: полное соответствие. Зависимости явно объявлены, изолированы в контейнере, lock-файл закоммичен. Отсутствие CI-проверок — вопрос процесса, не архитектуры.

**Статус: СООТВЕТСТВУЕТ (100%)**

- ✅ **Группировка настроек** — database pool (size, overflow, timeout), app (title, version, debug), log level

    log_level: str = "INFO"

> Обоснование: полное соответствие. Конфигурация полностью отделена от кода, секреты не имеют дефолтов.
