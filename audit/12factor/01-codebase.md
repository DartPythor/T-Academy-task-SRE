# Фактор 1: Кодовая база (Codebase)

## Методология 12 Factor App — Фактор I
> Одна кодовая база, отслеживаемая в системе контроля версий, много деплоев.

## Процент выполнения: 85% ✅

---

## Что сделано хорошо ✅

1. **Единый репозиторий (monorepo):** Проект находится в одном Git-репозитории. Это соответствует требованию "одна кодовая база".

2. **Git — система контроля версий:** Используется Git, что является стандартом индустрии.

3. **Чёткое разделение на компоненты:** 
   - `backend/` — серверная часть (Python/FastAPI)
   - `frontend/` — клиентская часть (TypeScript/Vite)
   - `Dockerfile` и `docker-compose.yml` — контейнеризация
   - `pyproject.toml` — управление зависимостями

4. **Использование Clean Architecture:** Кодовая база имеет строгую слоистую архитектуру (domain → application → infrastructure → presentation), что облегчает поддержку разных версий.

5. **Наличие метаданных:** В `pyproject.toml` указан автор, email, описание проекта, версия.

---

## Что нужно улучшить 🔧

1. **Отсутствует CHANGELOG / Release-notes:** Нет документированной истории изменений для отслеживания версий между деплоями.

2. **Нет тегов (tags) в Git:** В репозитории нет ни одной версионной метки (git tag). Для 12 Factor важно иметь возможность однозначно идентифицировать версию кода, соответствующую конкретному деплою.

3. **Единственный коммит:** Вся кодовая база закоммичена одним коммитом. Это усложняет отслеживание изменений между деплоями.

4. **Не используется Git Flow или Trunk-Based Development:** Нет стратегии ветвления, что затрудняет параллельную разработку и изоляцию между деплоями.

5. **Нет файла CHANGELOG.md / HISTORY.md:** Отсутствует документ, описывающий, что изменилось между релизами.

6. **Отсутствует стратегия семантического версионирования:** Нет гарантии, что `pyproject.toml` версия 0.1.0 соответствует определённому Git-тегу.

---

## Шаги для улучшения 📋

1. **Создать CHANGELOG.md** с разделами для каждой версии (`[Unreleased]`, `0.1.0`)

2. **Создать Git-тег для текущего состояния:**
   ```bash
   git tag v0.1.0
   git push origin v0.1.0
   ```

3. **Внедрить стратегию ветвления** (например, Git Flow или GitHub Flow):
   - `main` — стабильная, готовая к деплою
   - `develop` — интеграционная
   - `feature/*` — для отдельных задач

4. **Привязать версию из pyproject.toml к Git-тегам:** Каждый раз при изменении версии в `pyproject.toml` создавать соответствующий Git-тег.

5. **Внедрить conventional commits** (`feat:`, `fix:`, `chore:`) для автоматической генерации CHANGELOG.

6. **Настроить CI-пайплайн**, который при мерже в main автоматически создаёт тег и релиз.

7. **Добавить мета-информацию в Docker-образы** в виде меток (labels):
   ```
   org.label-schema.build-date=
   org.label-schema.vcs-ref=
   org.label-schema.version=
   ```
